## What existing PWA users should expect

On the existing hostname, the website can serve the new name and artwork directly. Android Chrome WebAPK installations can receive an icon update after users reopen the app and the browser processes the updated manifest. On iPhone or iPad, adding the app to the Home Screen again may be necessary to get the new icon. Users can continue opening their existing installation in the meantime. [PWA metadata updates](https://web.dev/learn/pwa/update) · [Chrome manifest updates](https://web.dev/articles/manifest-updates)

A different hostname is a different origin. For this rollout, users who want a shortcut that launches the new address should install from that address, sign in there and re-enable notifications if desired. Keep the old install usable while they switch. The server-side portfolios stay with the existing project and database. [PWA identity](https://developer.chrome.com/docs/capabilities/pwa-manifest-id) · [Origin migration](https://developer.chrome.com/blog/seamless-pwa-origin-migration)

## Design decisions

- Use a warm paper canvas `#F8F6F0`, ink `#202529`, and secondary text `#565F62`. Give the wordmark, active navigation and primary action a deep aubergine `#542D49`. Use white on filled aubergine buttons. Reserve moss `#236146` and oxblood `#913E42` for signed gains, losses and clearly labelled status. Pale stone `#DCD8CF` is a decorative divider. Give input boundaries and keyboard focus stronger contrast.
- Set **Aldervain** in Georgia or the local system serif. Use the new compact mark at icon sizes. Use the bundled DM Sans for controls, tables and figures. Use tabular numerals, right-align comparable amounts, and preserve ₹, precision, dates and the app’s existing financial labels.
- Build hierarchy with alignment and space. Start with 32–48 px between sections on desktop and 24–32 px on phones. Give ledger rows a single bottom rule. Place ordinary summaries and charts directly on the canvas. Reserve enclosed surfaces and shadows for interactions that need a boundary, such as a dialog, menu or drop zone. Use one filled primary action per action group.
- Use direct headings such as “Overview” and “Client statements”. Remove taglines and decorative eyebrows. Keep time ranges, price timestamps, validation messages, charge explanations and anything else a user needs to interpret a number or complete an action.
